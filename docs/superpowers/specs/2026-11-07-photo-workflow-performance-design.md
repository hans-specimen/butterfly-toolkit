## 2. 八项要求

| 编号 | 必须解决的重复工作 | 可验证结果 |
|---|---|---|
| 1 | 蒙版临时 PSD 发布到正式路径后，仅 `workingURL` 改变就导致同内容角色图重新提取 | 同任务、同不可变快照发布前后只提取一次；正式 PSD 和归属仍校验 |
| 2 | AI 输入仍使用 Save for Web；工作流 AI 输出使用默认 PNG 压缩 | 所有工作流中间 PNG 采用已验证的快速无损保存；解码 RGBA、ICC、方向、尺寸不变 |
| 3 | 确认前先 refresh，再 extract，重复检查同一个要求保持不变的 PSD | 确认路径一次受保护的 `extractRoles(snapshot:)` 即完成已保存版本检查与角色读取；真正的手工刷新仍完整执行 |
| 4 | 建议、预览、确认分别准备同一份全尺寸分析，缓存满两条就整体清空 | 共享有界分析缓存，同键并发请求合并；只淘汰最久未用项，优先可见标本 |
| 5 | 预览生成一张裁切位图后直接丢弃 | 删除无消费者的额外位图生成；Canvas、精确几何检查、过期任务门禁仍有效 |
| 6 | 同一角色图在渲染时重复解码；发布时两个相同副本各解码一次 | 单次渲染每个源文件只解码一次；复制后以已验证的字节身份复用检查，保留发布事务 |
| 7 | 每面所有服务完全串行，CPU、AI 与 Photoshop 不能重叠 | 受限并发：PS 一路、AI 一路、独立导出最多两路；两个蒙版任务可以错峰执行，保留检查点和恢复语义 |
| 8 | 每面重新启动 Python、载入模型、传入 GPU | 同批连续推理复用一个进程和固定模型；一次只执行一项推理，结束或暂停后释放 |

## 3. 不得改变的结果和行为

- 源 JPG、用户已有 PSD、已发布成品不能作为性能实验的写入目标。PS 写入测试使用独立临时副本。
- 未保存、保存中、角色被删除／合并、源版本改变、外来同名文件、符号链接越界，仍应拒绝或要求刷新。
- 原始堆栈组、共同调整组、底图、抠图及可编辑蒙版保留；画布外可恢复像素和坐标起点不能丢。
- 自动构图优先完整主体、真实背景和居中；空间不足时对称减小留白。整数取整中心误差最多半像素，手动偏移继续有效。
- 高清仅使用已确认的旋转裁切，不额外缩放，JPEG quality 保持 `0.82`。
- 4K 为 `4096 × 4096`、默认安全边距 `256 px`，当前 UI 边距范围 `0...512`；保留原透明 Alpha、触角、缘毛和尾突，不再次自动旋转。
- 预览天蓝色为 `#74BFFF`；橙色实线安全框、绿色虚线主体框及无刻度横线的滑块保留。预览背景不写入成品。
- BiRefNet revision 保持 `5d6b6f8adcb5b417c871b1d84ceaae9871355b7f`，`FP32`、`2048 × 2048` 输入、现有白底合成／插值／归一化／sigmoid／Alpha 恢复规则不变。不开启 CPU fallback、不量化、不训练、不下载模型。
- 不删去保存状态、内容身份、文件归属、版本栅栏、原子发布和中断恢复检查。优化的是重复工作，不是检查覆盖范围。
- 现有 PNG 中间缓存没有收据时仍可重新提取；收据损坏或图片哈希不匹配时不得使用旧图。
- Photoshop 自动操作继续通过 `PhotoshopExecutionCoordinator` 持有跨 await 的独占租约。人工编辑保留优先权。
- 旧 manifest 可读，单面失败只重试失败面，双面确认不批准未选中标本；旧异步结果不能覆盖新版本。
- 不新增运行依赖、通用任务框架、用户端性能设置或自动清理原文件的功能。

## 5. 接受标准

1. 每项有能检出原重复工作／竞态的测试，不能只断言最终文件存在。
2. 第 1、3、4、5、6、7、8 项分别提供提取次数、PS 调用次数、prepare 次数、无用渲染次数、解码次数、并发峰值、模型加载次数的证据。
3. 修改编码、解码、缓存或调度后，原始 RGBA 与色彩元数据对照通过；不可只比较 Swift 的预乘 sRGB 像素，因为它可能掩盖完全透明像素的 RGB 变化。
4. 有限并发及常驻模型以 1、2、4 面验证；阶段开关、取消／暂停、重启、手工保存、输出冲突测试继续通过。
5. 单项跑分区分首次和复用；最终记录用户操作到完成的总时长、各阶段耗时和内存。采用相同 fixture、Release、至少三次取中位数；未实测的收益写“未测”。
6. 性能实验出现像素／Alpha 差异、内存失控或恢复回归时，保留已通过的前序优化，回退有问题的单项，不以放宽验收阈值完成任务。
