## 2. 方案选择

用户选择：相邻 PS 操作尽量在一次打开期间完成；合成时顺便准备 AI 输入；评估 AI 全部完成后再集中写回。以下两种调度必须保留可对照能力：

- **现有交错模式**：最多两个 matte 面任务在途，PS 一路、AI 一路。是已通过的默认与回退路径。
- **候选集中模式**：全批堆栈获准后，严格分为全批补齐／验证输入 → 单路 AI → 等待 worker 完全退出 → 串行安装。输入阶段完成前不启动 worker；AI 段不发 PS 调用。结果逐面持久化，全批 matte 获准后才进入几何与导出。减少 PS／AI 同时重负载，但会失去部分重叠收益，是否更快待测。

不选“每面从安装直接走到成品”的大改方案：当前即使检查关闭，后续阶段也要求全批 matte completed；改变它会改变失败面如何阻挡整批，超出本轮。也不让全部 PSD 跨整个批次常驻：当前 24 GiB 机器已有明显内存负担。

实施选择由阶段实测决定：输入融合、PS 操作内复用、调度模式分别评估，可只保留有收益的部分；不把集中模式写成必然更快。

## 3. 候选流程及可合并边界

| 区间 | 可合并的实际工作 | 必须独立保留的逻辑完成点 |
|---|---|---|
| 合成结束 → AI 输入 | 保存分层堆栈后，在同一次 PS 打开期间从副本导出 PNG；禁止把蓝色预览底合入输入 | PSD 发布／归属和快照先有效；PNG 验证、版本绑定及 manifest 写入另外完成 |
| 全批输入 → AI | 输入已就绪时直接复用；缺失／失效时只补输入；同批单路 worker 顺序推理 | 每面 MatteArtifact 独立验证并落盘；不能全部完成才一次写清单 |
| 蒙版安装 | 同一现有 PS 独占租约内，复用打开的工作／暂存文档进行保存、capture、验证 | prepared 安装事务、原子发布、published 后验证、清除 pendingInstall 顺序不变 |
| 几何应用 | 同一次 applyGeometry 服务内连续变换、保存、capture、角色提取 | geometryApplySourceVersion 先落盘；保存后读回；未知中断不得盲目再次旋转 |
| 最终输出 | 复用已有最终角色与任务 6 解码路径，PS 不参与 JPG／4K 渲染 | 高清和 4K 各自验证、收据、原子发布与完成字段，失败不撤销另一项成功 |

本轮不跨服务的 await 边界删除当前源验证，不把上一个租约里取得的 metadata 当作后来仍然有效的依据。几何计算仍使用现有 PSD 角色读回，不改成直接用 AI Alpha 代替，以免微小差异改变裁切。

### 3.1 合成顺带输入的失败与恢复

1. 保留原分层堆栈，导出只操作临时副本；沿用任务 2 的标准 sRGB 8 位快速路径及其他输入旧路径。
2. 最终 StackPNG 绑定已验证的正式堆栈 `contentVersion`，保存尺寸、方向、色彩及 PNG 哈希；不得根据“同名文件存在”采用旧输入。
3. PSD 已成功而额外 PNG 导出失败：返回成功 PSD，输入为空，后续只补 PNG；不得把整个合成标为失败或覆盖 PSD 重做。PNG 缺失／坏图不是可用结果。
4. PSD 发布失败：候选 PNG 不可被推理；孤立文件只在本任务临时空间保留或清理，不能登记为成功。
5. 崩溃在 PSD 已发布而 manifest／PNG 记录尚未保存：沿用归属、源指纹、初始堆栈版本校验恢复 PSD，必要时重新导出 PNG，不重新景深合成。无需新增长期导出事务协议。
6. 打开合成检查时，预备 PNG 可以存在，但不得启动 AI；用户修改 PSD 后必须重新检查版本并使旧输入／旧 AI 结果失效。

### 3.2 PS 文档寿命

- 仅延长**单个现有 bridge 服务的独占租约内**所需文档寿命，不跨检查点、人工编辑等待或全批 AI 阶段保留自动会话。
- 用明确 documentID、规范化路径、owner 和版本绑定文档；不得仅依赖 activeDocument。重复进入 coordinator 会死锁，因此内部辅助方法必须是已持租约的 unlocked 调用。
- 自动持有的主工作文档默认最多一份；安装暂存文档、导出副本等算法必需文档按需存在，结束即释放，记录实际打开文档峰值。
- 用户预先打开的文档保持原有所有权规则；不得随意关闭用户文档，遇到未保存内容应拒绝而非自动保存或丢弃。
- 原子替换正式 PSD 前仍关闭旧磁盘版本对应的 PS 文档；替换后需要继续验证或原文档已打开时，重新打开新版。不得让旧内存文档随后保存覆盖新文件。
- 暂停先撤销后续授权；已经开始的不可中断 PS 操作持有租约直至安全收尾。清理不得因 Task 已取消而被跳过，也不能提前开放人工编辑。
- PS 文档 ID 只在当前进程／操作内有效，不写入 manifest 供重启盲用；PS 退出后从磁盘状态恢复。

## 4. 检查点、全批边界与失败策略

| 条件 | 必须表现 |
|---|---|
| 合成后检查开启 | 整批等待确认；提前生成 PNG 不等于批准 AI |
| 蒙版后检查开启 | 所有获准安装完成后进入整批检查；不能提前裁切或输出 |
| 几何检查开启 | 可计算建议，不应用旋转裁切；仍按完整标本双面确认 |
| 4K 检查开启 | 只准备布局；确认双面后才发布 4K |
| 检查关闭 | 按现有自动推进；全批 stack／matte 边界仍保留 |
| 单面输入／AI 失败 | 该面 failed，其他面按既有失败分类继续完成本阶段；不自动排除失败标本，不放行后续整批边界 |
| AI 会话致命错误 | 保持任务 8 的失败锁存；同次自动处理不能为后续面重启 worker；显式重试才新建会话 |
| 集中模式某面失败 | 等所有已派发 AI 安全结束、worker 退出后，只为具有有效持久化结果的面安装；失败面继续阻挡几何 |
| 暂停／批次切换 | 停止新派发、取消可取消工作、排空 PS 操作；切换成功前清单必须持久化，旧结果不能回写新批次 |

四开关的全部 16 种组合、整只选择／未选中标本、换输出目录、关闭重开，都必须有普通 suite 覆盖。

集中模式只能增加 matte 内部的“准备／推理”和“安装”调度子阶段，不新增用户可见 WorkflowStage。仅有 AI 结果时 matte 仍未 completed／waitingReview；存量 manifest 缺少缓存时走原补做逻辑。不能为了复用 execute 而在安装子阶段偷偷再次推理。

输入／AI 子阶段执行时使用现有 matte.running；成功缓存写入后，使用带 revision 校验的内部事件回到 matte.pending 并持久化，递增 revision、保留缓存，不写 outputVersion／confirmedVersion，不触发 stageCompleted、清理或自动确认。各子阶段只从当前 eligible 的 pending 记录派发；失败仍为 failed，暂停归回 pending 的语义不变。输入准备、AI、安装在一次受 runStages 保护的阶段调度内顺序执行，不能落回外层默认交错循环。子阶段之间重启从持久化字段判断：有效输入／AI 不重复做，已安装 PSD 沿原恢复读回路径验证，不因旧 snapshot 缺 roles 就重新推理。

## 6. 新旧实测设计

### 6.1 四种消融配置

使用同一版本二进制的内部测试配置控制各项开关，非用户设置，默认保持上一轮已验证行为直到最终验收：

| 配置 | 合成顺带 PNG | PS 服务内文档复用 | matte 调度 |
|---|---|---|---|
| A 当前基线 | 否 | 否 | 已验证双路交错 |
| B 输入融合 | 是 | 否 | 同 A |
| C PS 合并 | 是 | 是 | 同 A |
| D 候选保守方案 | 是 | 是 | 先全批 AI、退出 worker、再安装 |

调用次数／事件断言证明开关确实选择不同路径；不得“新旧”都运行同一 helper。最终比较最优候选与 A，不能只比较最慢的串行版本。旧 237／215 秒仅作历史参考。

### 6.2 三层测量，避免焦点合成变动掩盖结果

1. **保存堆栈后的路径等价**：在同一次合成得到的相同分层 PSD 内容上，比较关闭前的输入导出与重新打开后导出。逐面各三次；比较原始 RGBA、Alpha=0 的 RGB、ICC 原字节／色彩块、方向、尺寸及位深。不得只比较预乘 sRGB 或肉眼。
2. **同堆栈的可控后半程**：相同不可变原堆栈、全新 owner／workspace，1／2／4 面各配置至少三轮、交替／轮换次序；1 面仍采用另一面已完成的半对重试夹具，不宣称单面完整批次。A 对 C 分离 PS 文档复用收益，C 对 D 分离调度收益。B 的合成融合在本层不发生，不得把预生成 PNG 的准备成本藏在 setup 中来宣称收益。
3. **真实完整批次**：复制原 JPG，分别使用一只／两面（6 张）与两只／四面（12 张）全自动流程，从首次实际 stack 服务开始计时到全部 HD／4K 发布且 worker／PS 操作排空；两种规模的 A/B/C/D 各至少三轮，最终四面候选与 A 至少五轮（可包含前面同条件三轮）。复制 fixture 在计时外，合成、输入导出、各次保存验证在计时内。另记录用户启动到完成墙钟，不包含人工确认停留时间。

新 JPG 合成跨运行可能不确定：先比较各轮堆栈的解码像素／ICC及结构，不能比较包含时间信息的 PSD 文件字节作为画质判据。若堆栈已不同，不把后续差异归因于优化，也不放宽 Alpha 阈值；报告完整批次对照的限制，保留相同堆栈的精确等价门禁。至少为每个候选完整输出链增加同一固定堆栈的对照。

### 6.3 指标与计时范围

- 总墙钟、首次可用结果、每面／阶段时间、AI 首面／后续面、worker 启动及真实模型加载次数。
- 分开记录 PS 租约排队、脚本往返、打开／关闭、合成、安装、几何变换、save、inspect、capture 拷贝、SHA-256、角色 PNG 编码、像素验证、manifest、最终 render／publish；不能将包含等待的 service 累计时间当纯计算时间。
- 记录打开／关闭／保存／提取次数和实际文档峰值；插桩默认关闭、按操作记录，禁止主路径逐像素日志。重叠服务不相加当总耗时。
- 每秒采样测试 App／子进程／PS RSS、系统压力、swap 前后；记录已有 MPS 分配端点与清池后值，明确不等于真实 GPU／统一内存峰值。固定机器、版本、模型、输入和设置，记录初始 swap、缓存冷暖、热状态；不并行编译或运行其他本任务重负载。
- CPU/GPU tracing 单独做诊断，不混入正式速度数据。已有 65.3／85.2 秒只能提出资源争用假设，不能保证可追回全部差值。
- 恢复专项额外计时，不混入无暂停样本：暂停发生在 AI 活动中、安装 prepared/published、几何保存前后及导出发布边界；核对重启推理／安装／旋转次数和原文件哈希。

### 6.4 放行与回退

必须同时满足：普通全套及新增恢复测试全绿、同输入 Float32 Alpha 精确相等、原始像素／色彩一致、几何解一致、保护文件哈希不变、无持久化或租约退化。不同输入内容的跨合成结果不得用于精确等价结论。

本轮提议的保守默认切换门槛：固定堆栈后半程与完整四面批次均不退化；完整四面最终五轮的中位数至少降低 5%，且至少四轮配对更快，才选择新默认。2 面中位数不得退化超过 5%；1 面诊断不得出现可重复的明显退化。阈值用于抵抗测量波动，不是预计收益。若其他进程／热状态使条件不成立，重测或保留旧默认，不调松阈值凑结果。

若只合成融合或 PS 操作复用有收益，就只启用这些部分；集中模式无收益时保持交错。若出现持续内存恶化、清池后逐面增长、额外 swap／高压力与明显长尾相互印证，退回受影响部分。单个 driver 端点不直接等于内存失控；保留全部样本及判断依据。
