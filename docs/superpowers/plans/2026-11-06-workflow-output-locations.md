# 工作流输出位置调整

**目标：**按本轮用户要求取消统一输出目录，PSD 与输入照片放在同一文件夹，AI 临时 PNG 自动清理，堆栈原图与 PNG4K 各自选目录，到 PNG4K 结束。

**方案：**沿用现有 SwiftUI、批次清单和执行器。批次记录由应用自动管理；新批次保存两个独立导出目录，旧清单保持可读。保留文件所有权和原子发布检查。工具箱独立的衍生图片功能不变。

## 实施与检查

- [x] 输出位置：扩展 WorkflowModels / PhotoWorkflowStore 的目录记录与校验，新增目录缺失、路径逃逸与旧清单回读测试。
- [x] 执行器：PSD 直接保存到输入目录，导出前校验各自目录，停止执行衍生阶段；测试实际目的路径、补选路径、同名文件保护和结束状态。
- [x] 临时文件：仅清理本批次拥有的 AI 输入/结果 PNG，在蒙版成功保存并记录后清理；失败保留重试材料。验证不会删除外部文件。
- [x] 界面：第一步和对应导出步骤提供目录选择；移除统一输出位置及衍生设置；构建并运行工作流回归测试。

## 实施决定

用户已明确确认：景深合成、蒙版回写、构图和 PNG4K 的所有检查点均可取消，直接自动处理到 PNG4K。只要保留任一检查点，初始导出目录可留空；执行到缺少目录的导出步骤时等待补选。

旧清单的衍生枚举和记录字段仅用于兼容读取，界面和执行器不再提供或运行该阶段。内部批次记录位于应用支持目录的独立批次文件夹，用户可通过“查看文件 → 批次记录”找到。

## 风险检查

输出目录可以已有内容，任何冲突都不得覆盖不属于当前任务的文件。旧批次在已保存的 PSD 上继续。清理只限程序管理的临时区。目录变更不得让旧异步结果发布到新路径。批次恢复继续使用已保存的所有权与版本校验。
