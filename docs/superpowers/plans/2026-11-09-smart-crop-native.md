# 独立智能裁剪改造实施记录

依据：本次对话已批准的方案及最后的界面简化要求。

目标：无需外部 AI 引擎或 Photoshop，复用照片流几何算法；默认自动扶正、居中、10% 目标留白，仅提供 5:4／自适应。

## 约束

- 保留照片流持久化字段、版本校验和 Photoshop 调度，不改其默认参数。
- 独立工具使用 Vision 和背景色差分，支持手动两点与主体框；原始照片不作为测试输出。
- 预览和导出使用同一几何方案，导出前后检查源身份，保留安全 JPEG 写入。
- 初始在独立本地开发分支完成工作；安装、提交和推送依照用户后续授权执行。

## 实施顺序

1. 提取共用几何模型、主体支持区域和求解器到 Core/ImageProcessing；照片流保留文件读取适配。运行原有几何测试确认行为保持。
2. 重写独立处理入口：方向归一、格式正确的 Vision 蒙版、色差后备、手动范围、共用求解与 JPEG 渲染。先验证浮点蒙版、整数尺寸和坐标方向的失败用例，再实现。
3. 原生 SwiftUI 表单与预览工具栏；逐图调整、两点／矩形交互、有界缓存、源版本和批次取消。测试逐图隔离、过期请求、导出一致性与文件保护。
4. 运行完整常规 Swift 测试与版本工具检查，更新现行说明，独立复核改动。真实照片及 Photoshop 验收与自动测试分开报告。

## 重点边界

- EXIF 方向和顶部坐标；浮点蒙版不能按字节解读。
- 固定比例临界取整、旋转露空、细小分离附属物。
- 自动角度不可靠时提示人工确认，不默默批量导出。
- 人工范围只决定完整保留区域，不冒充自动识别。
- 源文件改变、旧异步结果、同名输出、处理中取消。

## 进度

- 已检查工作区原本干净，并创建本地开发分支。
- 已完成共用核心提取、本机识别与安全 JPEG 输出、原生面板和逐图人工修正。
- 原留白语义回归先失败；新实现统一为输出尺寸占比。浮点蒙版、方向、整数尺寸、EXIF 和源保护回归通过。
- 独立复核发现离页批次继续写入、灰度 JPEG 渲染失败、极小图后备采样越界；增加失败回归后修复，后备识别循环增加取消检查。
