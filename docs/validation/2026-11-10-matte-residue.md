# 2026-11-10 微弱蒙版残留修复验证

本记录是本轮素材回放的历史证据，不代表所有物种或新一轮模型推理验收。现行规则见[照片工作流](../PHOTO-WORKFLOW.md)，复现入口见[测试指南](../TESTING.md)。

## 问题与修复范围

旧支持区域会把细长、稀疏的分离残留当作可能的细毛，即使残留仅为 1～2/255 Alpha，也可能将完整主体边界扩展至画布边缘。之前排除完全透明底图像素的修复没有覆盖有效背景上的微弱残留。

本轮将远离可信主体、完全由弱 Alpha 组成的分离区域清零。连通边缘、触角、细毛及主体邻近的断续细节保留。AI 原结果先严格校验，派生清理后的蒙版和透明 PNG 再次校验后回写；分析使用同一清理规则。标准 sRGB 在 ImageIO 编码时可能丢失 iCCP，因此清理输出原样保留输入颜色块，未放宽 ICC、颜色像素或 Alpha 检查。

同时修复自动裁切后的翅顶坐标变换、人工检查显示画布外隐藏像素，以及把已经失败的构图当作有效旧方案验证而出现误导错误的问题。实际应用构图仍走严格校验。

## 后续复现：22_D 与 33_V

新一批次暴露两个此前验证未覆盖的问题：

- `33_V` 的远处分离残留有 60 像素，其中两个 Alpha 达到 20/255、22/255，旧规则因此保留整块。新增回归在旧规则上失败；新规则综合面积、平均／最高 Alpha 和距离判断，此样本恰好去除这 60 像素。相连触角、临近细毛及明显分离细节继续保留。
- `22_D` 自动裁切已完成，但原蒙版层仍保存完整底图 RGB，变换框为 5199 × 3496。前一轮在测试中临时应用蒙版，未验证产品默认选择的图层。修订后的真实测试直接读取保存后默认成品的边界，在旧代码上报“Visible finished layer still has mask”，确认能捕获原问题。

新人工定稿流程在自动回写和裁切后生成最上方「透明成品」，实际应用蒙版并选中该层；隐藏「抠图」备份保留原蒙版与完整 RGB。自动提取用成品像素与备份蒙版进行原有严格校验。人工刷新不重建成品。旧批次不自动生成成品，继续原来的蒙版编辑契约。

真实测试只读角色 PNG 和原 PSD，在临时目录建立独立 PSD 回放已保存蒙版，不重跑模型或修改原批次。除边界外，还核对默认选择层无蒙版、隐藏备份仍有蒙版、删除副本蒙版可恢复背景、最终可见成品逐像素一致以及原素材哈希未变。
