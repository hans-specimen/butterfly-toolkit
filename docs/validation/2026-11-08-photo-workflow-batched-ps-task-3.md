## 实现与边界

- 在已有 coordinator 租约内部保留临时文档句柄；不重复获取租约，不跨服务、面、暂停或重启复用，不将文档 ID 写入清单。
- Swift 保存文档 ID、规范化路径与随机 nonce；PS 的随机 nonce 对应 `putCustomOptions(..., false)` 非持久会话记录，包含 ID、请求路径、PS 实际 fullName 与是否由工作流打开；清理时 erase。每次使用核对 ID／路径／saved，重启或句柄失效报 stale；已有用户文档只借用，dirty 文档拒绝保存或关闭。
- 几何服务的 verify→修改／保存→capture→角色提取使用同一工作文档。安装分为暂存 PSD scope 与发布后的新 scope；原文件关闭、原子替换及需要时为用户重开都保留原顺序，旧句柄不穿越发布边界。
- capture 保留两次元数据检查、复制／哈希顺序和磁盘版本栅栏；第二次检查在复用时打开已校验的不可变／临时 PSD 副本，独立读取已保存内容，不把内存文档视为磁盘读回。
- 清理在 detached task 内等待完成才释放服务租约，取消不跳过清理。获取响应无法解码时仍按 nonce 清理。清理不继承文档 scope，但显式恢复观测 taskID，避免关闭耗时漏归属。
- 检查点、整批阶段边界、归属／安装恢复协议、几何与像素算法、输出参数均不变。Task 2 的不透明 PNG 限制保持原样。工作流默认仍走旧路径；是否启用留给后续验收。

## 单面真实对照

证据根 `/tmp/butterfly-batched-ps-task3-20261108/`，DerivedData `/tmp/butterfly-next-perf-build`。从既有 22_F 原始堆栈不可变 PSD（SHA-256 `54f113d8f9b466589c140350cf1e877da41d17de36f7e28fbd494d7db7ab8fc7`）复制两份，复用对应的既有 AI Alpha／前景；全部写入新隔离目录。真实测试只做安装、几何、角色与 HD／4K 输出。

默认路径正常执行；候选路径预先打开隔离文档模拟用户已打开状态，并在 prepared、published 各注入一次中断，恢复后检查文档新 ID 不同且仍保持打开。候选几何在保存、capture、角色提取和 scope 清理全部完成后、服务返回前注入一次中断；旧快照重试必须拒绝，随后 refresh 接纳磁盘版本，防止二次旋转。此故障点并非紧贴 save 的中断。普通测试另覆盖更早的 dirty／取消错误路径。

候选有额外恢复尝试，两组耗时不能直接作为公平性能 A/B；本项不宣称端到端速度收益，也不替代后续稳定整批验收。故障回合 cleanup 在实际执行后由 runner 抛错，内部 ps.close／peak 元数据没有回传，故成功回传的脚本观测可能少一次 close；ps.invoke 仍有记录。资源采样不等于瞬时精确峰值。

首次真实对照命令 86.874 s、测试体 45.506 s：默认侧完成，候选在首次暂存 PSD scope 内被 stale 校验拒绝，暂存 PSD 哈希仍等于原始文件，未发布。保留失败日志与产物；基准结果随后只读复用。

诊断发现原模拟环境误把 `$.global` 当跨脚本状态。恢复脚本通道后，最小 3.454 s 探针确认 acquire 后下一次 `do javascript file` 的 key 为 undefined，而 PSD 仍打开。改用 PS 非持久会话 descriptor；0.489 s 探针证实跨调用可读取，真实空白 PS 退出／重开后 key 缺失（`session-after-restart.txt`）。普通模拟每次调用重置 `$.global`，PS 重启清空 descriptor store，防止原错误漏测。

修复后首次候选侧回放命令 20.022 s、测试体 10.561 s 又被严格路径检查拦住：Swift 传入 `/tmp/...`，PS `File(...).fsName` 保留该拼法，实际 `doc.fullName.fsName` 是 `/private/tmp/...`。此前只检查实际路径就过早排除了路径因素；本次同时读取两种 File 表示确认差异。最终按 nonce 同时绑定请求路径与实际 nativePath，各自严格比对；ID、dirty、版本哈希检查均未放宽。新增 nativePath 别名普通回归。完整 Swift 结果在该最后路径修正之前；按用户要求，修正后只运行桥接类与候选侧真实回放，不再扩大套件。

另一次诊断阶段 PS 脚本通道超时，与上述数据校验错误分开记录：直调 AppleEvent 等待约 120 s，测试宿主诊断命令 146.507 s／测试体 120.292 s，最终还出现 XCTest 错误桥接的 NSDictionary/typeMismatch；随后限时 10 s 的最小脚本查询也超时，但版本查询与 UI 脚本正常。采样显示主线程在事件等待，没有证据将此超时认定为 nonce 缺失的直接结果。仅关闭两份已保存的隔离 PSD，正常退出／重开 PS 后脚本通道恢复；未强杀 PS、未保存或关闭其他文档。诊断脚本未写用户 PSD。这些等待是实际额外耗时，不计作成功性能样本。

路径修复后的 bridge 类运行命令 70.205 s：33 通过、4 跳过、1 失败；真实测试体 22.521 s。此次已完成候选安装与 prepared／published 恢复，失败是测试脚本仍用未归一的路径查找借用文档，而非文档被误关。只读检查确认已保存的新工作 PSD ID=171 仍打开。修正测试 helper 使用 POSIX realpath，输出前后 ID 证据；产品代码未再修改。旧隔离文档随后逐个关闭。一次临时清理脚本在关闭首个文档后继续访问它而报 Object is invalid，已加 break 并确认剩余旧测试文档全部关闭，未保存文件。
