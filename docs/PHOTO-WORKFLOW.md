# 照片工作流

本页说明当前实现、默认行为和未完成验收；历史实测见文末证据。代码位置为 `Butterfly Toolkit/Features/PhotoWorkflow/`。截至 2026-11-09，第二轮性能优化 Task 1–4 已实现，Task 5 完整择优尚未完成，候选未接入默认配置。

## 使用流程

1. 选择开始阶段：从景深合成开始时，JPG／JPEG 按自然文件名顺序每六张组成一只标本，前三张为正面 D，后三张为反面 V；从 AI 抠图开始时，读取已有的 `<名称>_D.psd`／`<名称>_V.psd`，自动配对并填入名称，忽略同目录 JPG。
2. 核对固定槽位与逐行名称；可替换、移除照片、交换正反面或排除整组。剩余未分组照片须明确排除；开始后新增照片不会自动加入冻结批次。
3. 配置本批次 AI 引擎，开始处理。失败项需要重试或明确排除，不能把部分成功视作全部完成。

已有 PSD 模式不重新景深合成，也不需要手动导出 PNG。缺面或后缀不明的 PSD 必须补齐或明确排除，重复面文件会报错。此模式直接更新选中的原 PSD，开始回写前保留不可变原始快照；拒绝接管 Photoshop 中未保存、已属于其他批次或已有工作流角色的文件。继续既有批次请打开其清单。PSD 文件名保持不变，名称栏调整仅用于后续导出命名。

新建批次采用以下四步；旧批次保留原流程，点击“切换到人工定稿流程”后采用新规则。

| 阶段 | 处理与检查 |
|---|---|
| 景深合成／已有 PSD | 每面三张合成为分层 PSD，或接管配对的已有 PSD |
| AI 抠图与回写 | 自动准备 PNG、推理并将蒙版写回 PSD |
| 裁切矫正与人工检查 | 自动应用有效构图；无解时保留当前 PSD 并说明原因。此步必须停下供完整人工检查 |
| 导出 | 只预览 4096×4096 PNG；一次确认所选标本两面，同时导出底图 JPEG 和透明 PNG |

第三步可反复打开 PSD，修改蒙版、应用蒙版、替换图层、调整画布、角度和堆栈内容。保存后刷新，不需要选择修改类型；点击“确认所选两面并进入导出”读取最终保存版本，此后不再自动抠图或裁切。导出前再次检查保存版本，未保存或预览后又修改的 PSD 不能沿用旧确认。

旧批次的四个可选检查点与独立导出目录继续兼容。完成旧批次 AI 抠图及检查后才可切换；显式迁移时先备份清单，复用已完成的 AI 结果，不重新应用几何处理；历史输出记录保留，既有文件不删除。

## 文件位置与输出约束

- 新合成的工作 PSD 与输入照片同目录，名称为 `<标本名>_D.psd`／`<标本名>_V.psd`；源照片不改名、不覆盖。已有 PSD 模式使用冻结的原文件路径。
- 新流程在输入文件夹内创建 `<输入文件夹名>_堆栈原图` 和 `<输入文件夹名>_4K_PNG` 子文件夹，无需选目录。新输出统一使用 D／V 后缀；旧批次保存的历史路径继续有效，不自动改名既有文件。内部批次记录在应用支持目录的 `Butterfly Toolkit/PhotoWorkflow/<UUID>/`，通过“查看文件 → 批次记录”定位 `batch.json`。
- `.work` 保存快照及恢复材料。蒙版成功回写且阶段持久化后，仅清理本批次受控路径中的 AI 输入／结果 PNG；失败时保留重试材料，不应手动清空整个工作目录。
- 旧清单仍兼容历史输出子目录和派生字段；当前工作流不执行闲鱼、1K 白底或紧裁素材阶段，独立图片工具另行使用。
- 自动几何分析使用蒙版与底图 Alpha 的乘积，排除完全透明背景中的不可见残留；不修改原蒙版，不通过提高统一阈值删除触角和细毛。
- 高清构图支持自适应、5:4、22:17（11:8.5）、1:1；默认相对留白 10%。自动构图优先主体居中，背景不足时减少留白，不补背景、不截断主体。
- 堆栈原图 JPEG 质量为 0.82。PNG4K 为 4096×4096 透明图，默认安全边距 256 px，界面可调 0…512 px；预览底色不写入输出。
- PNG4K 使用已确认的姿态重新排版，不重复旋转；只改其布局不重跑 AI，也不改已确认高清构图。完整细节 alpha 保留，分析用的主体支持区域不能替换原蒙版。

## 状态、人工编辑与恢复

`WorkflowStateMachine` 管理每面的 pending、running、waitingReview、completed、failed、excluded；`WorkflowExecutor` 调用外部服务并保存结果；`PhotoWorkflowStore` 管理界面草稿、选择和预览。

源文件指纹、阶段修订、PSD 内容版本和产物配方共同约束结果。异步返回后重检版本；新预览立即撤销旧确认资格，只有匹配请求令牌和保存版本的结果可确认。堆栈、抠图各有整批阶段屏障，不能让先完成的一面越过整批检查。

工作 PSD 保留原始堆栈、共同调整组、底图、抠图及可编辑蒙版。角色图像记录完整可编辑范围、像素原点和可见视口；坐标使用 x 向右、y 向下。几何角度相对于当前保存版本，写回后归零并更新裁切坐标，防止重复变换；裁切保留框外可恢复像素。

- 人工编辑先从界面打开工作 PSD，自动队列暂停并让出 Photoshop；同一面可重复打开。切换另一面前先校验并刷新上一面的保存结果，未保存时不自动保存、关闭或丢弃用户修改。
- 新流程的最终 PSD 必须有唯一的「共同调整」组和组内唯一的像素图层「底图」。底图按当前画布导出 JPEG，不重新构图；透明缺口仍会拒绝导出，不自动补色。
- PNG 使用共同调整组内除底图外最上方可见像素图层，可任意命名，支持保留蒙版或已应用蒙版。其他备份图层不参与输出；不要求最终前景 RGB 与底图相同。组蒙版或依赖其他图层的剪贴关系须先落实到导出图层。
- 刷新读取不可变保存快照，并严格验证归属、尺寸、方向、ICC 和 Alpha。源版本变化使下游确认失效；不通过修改清单完成字段绕过错误。旧流程仍使用分类刷新和固定角色约束。
- 暂停停止新派发并取消可取消任务；不可中断的 PS 操作须安全收尾。重开 `batch.json` 时，中断的 running 记录退回 pending，修订递增；只接纳能验证身份的已完成成果。
- 清单采用原子写入，并保留上一份有效 `.previous` 清单。图片发布凭据独立于清单，先验证候选、归档旧版本，再原子替换；外来同名文件不覆盖、不认领。
- 蒙版安装保留 `pendingInstall` 恢复记录；几何写入中断保留来源标记，禁止盲目再次应用。保留 `.workflow-history`、归属凭据、PSD 快照和必要恢复材料。

## 当前性能配置

| 配置 | 当前正式路径 |
|---|---|
| 蒙版调度 | `interleaved`，最多两个面交错；PS 单路、AI 单 worker 单路 |
| 导出并发 | 最多两路；堆栈和几何阶段按单路派发 |
| 模型会话 | 同批连续推理复用模型，阶段结束、暂停或切换批次时关闭并等待退出 |
| 几何缓存 | 同会话共享，最多 4 项、保留数组估算上限 512 MiB；不是进程内存上限 |
| 角色缓存 | 以任务和不可变保存版本定位，复用前仍校验保存状态、归属及文件哈希 |
| 合成顺带 PNG | `prepareStackInput=false`，默认关闭 |
| PS 服务内文档复用 | `reuseDocumentsWithinOperation=false`，默认关闭 |
| 集中调度候选 | `phased` 仅内部可选，默认关闭 |
| 细分性能观测 | observer 默认 nil，无用户性能开关 |

合成顺带 PNG 候选仅接受全不透明输入；含透明像素时回退重新打开 PSD 导出。文档复用仅限单次已有租约，不跨人工检查点常驻。集中候选按全批准备 → 单路推理 → 等待 worker 退出 → 串行安装运行；仅保存 AI 结果不算抠图完成，安装段不能偷偷补推理。

## 已有实测与限制

真实 Photoshop、AI、暂停恢复和 Release 副本界面已有实测，不能继续描述为“尚未做过真实测试”；各报告仅证明其列明的样本和边界。

- 第一轮任务 7：固定已保存堆栈到四面高清／4K，三轮中位数 237.161→215.044 s（9.3%）；另有真实暂停恢复。任务 8：连续四面 AI 106.559→92.176 s（13.5%）。两者范围不同，收益不可相加，也不能外推为新 JPG 全链路同幅提速。
- 第二轮任务 1：21 次正式实图运行中 19 次通过、2 次完整 JPG 流程失败。完整两面和四面均只有 2/3 成功，透明源像素与前景一致性校验仍可能拒绝新合成输入；稳定完整基线未通过。
- 第二轮任务 2：直接融合 7 对中 6 对精确相等，22_U 的 2,394 个 alpha=0 像素 RGB 不同；受限候选与透明回退验证不能改称通用融合全通过。
- 第二轮任务 3：真实文档生命周期、安装恢复和输出等价已有证据；候选含额外故障恢复，不是公平的性能 A/B。
- 第二轮任务 4：单次两面 C/D 为 120.633／127.904 s，集中候选慢 6.03%，没有提速或内存下降证据，保持默认关闭。
- 仍未完成：最终用户蒙版质量认可、20 只／40 面比较集、真实画面呈现的 warm p95、GPU／统一内存精确峰值及长期混合负载。几何计算或 Store 完成计时不能替代屏幕呈现延迟。

## 未完成的 Task 5：完整对照与默认择优

下列要求保留自原验收约定；它们是待执行工作，不代表本次文档更新启动新测试或改变默认配置。先核对任务 1–4 证据、已知失败和审查结论，再进行最终选择，不新增优化。

固定同一二进制的内部配置：A=旧 stack／不复用文档／交错；B=合成顺带 PNG／不复用文档／交错；C=合成顺带 PNG／复用文档／交错；D=合成顺带 PNG／复用文档／集中。必须用事件／调用次数确认实际走到的路径；当前基线是 A，不用历史 237 秒串行结果代替。尚不支持的完整批次配置不能借标签冒充已接入。

三层测量分别进行：

1. 同一次合成的相同分层 PSD：关闭前与重开后的输入导出逐面各三次，精确比较原始 RGBA（含 alpha=0 的 RGB）、ICC 原字节／色彩块、方向、尺寸、位深。
2. 相同不可变原堆栈的可控后半程：全新 owner／workspace，1／2／4 面各配置至少三轮，轮换次序；单面是半对重试夹具，不是完整单面批次。此层不发生合成融合，输入准备成本不能藏入 setup。
3. 新 JPG 完整批次：6 张／两面、12 张／四面的 A/B/C/D 各至少三轮；最终四面候选与 A 至少五轮配对，可包含同条件前三轮。从首次实际 stack 服务到全部 HD／4K 发布及 worker／PS 排空，合成、输入导出与保存验证计时；夹具复制在外，另记启动到完成墙钟，排除人工停留。

新合成跨轮可能产生不同像素，须先比较堆栈解码像素、ICC 和结构；不同输入的后续差异不能归因于优化，也不能放宽 alpha 阈值。每个候选完整输出链仍须有同一固定堆栈对照，精确比较 Float32 Alpha、原始像素／色彩和几何解；既有安装误差容限不能替代跨配置精确相等。

固定机器、版本、模型、输入、设置、缓存冷暖与热状态；记录初始 swap，不并行编译或运行其他本任务重负载。模型固定 BiRefNet revision `5d6b6f8adcb5b417c871b1d84ceaae9871355b7f`、FP32、2048×2048；预处理、插值、白底合成、归一化、sigmoid、alpha 恢复和浮点结果不变，不切后端、降精度、训练或下载模型。JPEG／PNG4K 参数、分层结构、可恢复像素、全部版本／归属／发布保护保持不变。

记录总墙钟、首个结果、每面阶段、实际模型加载数，以及 PS 排队／打开／关闭／保存／提取、哈希、清单和渲染发布成本；嵌套或重叠时间不可相加。每秒采样应用／子进程／PS RSS、系统压力、swap 与 MPS 分配端点，注明不是 GPU 峰值；tracing 另作诊断。

额外真实恢复专项覆盖活动 AI 中暂停、安装 prepared／published、几何保存边界、输出发布中断和人工编辑，记录推理／安装／旋转次数、迟到发布、worker 退出和人工获租顺序；不混入无暂停速度样本。普通测试须保留全部 16 检查组合、双面选择、未选标本、目录更换与旧清单恢复。

放行须同时满足：质量精确等价、恢复／租约无退化、保护文件哈希不变、普通及恢复测试通过；固定堆栈后半程和完整四面不退化；完整四面最终五轮中位数改善至少 5%，且至少四轮配对更快；两面中位数退化不超过 5%，单面无可重复的明显退化。环境不具可比性则重测或保留 A，不降低门槛。

只启用确有收益的部分；持续内存恶化、清池后逐面增长、额外 swap／高压力与长尾相互印证时回退相关候选。全部样本与失败须保留，无胜出者就保留默认交错路径。

最终选择后补充 `testLiveConfigurationMatchesAcceptedCandidate` 行为测试，验证正式初始化实际采用已放行配置，并保留内部对照开关，不能仅凭实验入口推断正式路径。

最终运行 Toolkit Swift 全套、版本工具 Python 测试，以及所选外部 AI 引擎的 `scripts/test_toolkit_bridge.py` 全套回归，再做无测试变量的正式 Release 构建，并在原应用空闲时使用独立应用和全路径副本验收。新证据目录须不存在且全部写目标限制在临时根；原照片、PSD、成品和清单只读，前后保护哈希一致并恢复原页面选择。锁屏或缺权限记未验证。报告逐项“启用／保留旧路径／未验证”、资源与文件体积代价，经独立审查后交付；安装和推送仍按届时明确授权。
